## 목표

[M4] 파일 레이어 강제와 사용성: 세션 시작이 열린 노트만 읽고 첫 답이 다음 할 일을 말한다

https://github.com/rimoir/dam/issues/42

## 완료 기준

- 세션 시작용 출력이 현황판의 열린 줄과 열린 작업 하나의 상태 파일만 담고(도구 전환 때는 로그 마지막 5줄을 더함), 출력이 정해 둔 글자 상한 이하인지 CI 테스트가 확인한다
- Claude Code와 Codex 각각에서 새 세션, /compact 뒤, 도구 전환을 각 3회 했을 때, 첫 답에 작업 이름과 상태 파일의 다음 할 일이 나온다. 기록은 이 에픽의 작업 노트에 남긴다. (로그인 세션 확인은 HR P 게이트. M1 #2, M2 #3과 같음)
- 시작 주입에는 로그 전체가 들어가지 않는다(도구 전환 때의 마지막 5줄만 예외). 로그가 상한을 넘으면 앞부분이 작업 폴더의 `log/`로 옮겨지고 옮긴 내용은 바뀌지 않으며, 테스트가 이를 확인한다
- 상태 파일이나 로그가 상한을 넘긴 PR은 CI가 실패한다
- 세션 시작 출력의 실행 시간 중간값과 주입 글자 수가 측정되어 이 에픽의 작업 노트에 있다
- dam의 열린 작업이 현황판과 노트 네 파일(목표, 상태, 로그, 결과)을 쓰고, 규칙 원본에서 '폴더를 통째로 읽어라'와 '현황판과 상태만 읽어라'가 서로 다르게 적힌 모순이 없어진다
- 두 도구에 SessionStart 훅(compact 포함)을 쓰는 결정이 결정 기록(ADR)에 남아 있고, Codex에서 훅이 바뀔 때 필요한 신뢰 검토 절차가 README에 적혀 있다
