# 결과 78

## 결과

결정 줄이나 승인 줄을 바꾸면 상태는 문제이고, 이유에 경로와 바뀐 줄이 들어간다. 원래 내용은 시작 때 핸들 폴더에 둔다. 수거는 워커 폴더를 링크를 따라가지 않고 읽어 줄 단위로 비교한다. 줄당 200자, 최대 8줄이고 제어 문자는 이스케이프한다. 그 밖 파일은 경로만 적는다. 코드와 git은 워커 폴더에서 돌리지 않고, 그 폴더에 쓰지도 않는다.

검증은 수거가 성공한 뒤에만 돈다. 가짜 claude로 돌린 출력은 검증 통과, 검증 실패, 네트워크 실패 `NET_FAIL URLError`, 인증 정보는 `TOKEN ABSENT`와 빈 git 설정과 임시 HOME이다. 실제 모델은 부르지 않았다.

시작 시간. 데브 박스의 실제 Claude Code 2.1.317, head `3ad4eeaff3ad7d5a9c0aedc4b58ce67f490f4dda`에서 orchestrator start의 단위는 `Claude 시작`이다. 명령부터 첫 stream-json 이벤트(system/init)까지 5회는 0.315, 0.315, 0.312, 0.420, 0.335초다. 정렬하면 0.312, 0.315, 0.315, 0.335, 0.420초이고 중간값은 0.315초다. 기준 15초 이하다. 출처는 https://github.com/rimoir/dam/issues/78#issuecomment-7210578911 이다. Codex는 HR P PC에서 #77 Codex 단계와 함께 측정 예정, 미측정이다.

## 교훈 후보

- 테스트가 제품과 같은 PATH 조회를 쓰면, 도구가 있는 곳에서만 유료 호출이 나간다.
- 워커 작업 폴더와 handle 저장 위치가 같으면 워커가 자기 시작 기록을 읽는다.
- 워커가 결과 칸만 쓰면 수거가 그 폴더의 코드나 git을 돌릴 이유가 없다. 경로를 더 막는 대신 실행을 뺀다.
