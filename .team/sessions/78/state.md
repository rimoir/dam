# 상태 78

## 지금 상태

수거가 성공이면 네트워크와 인증 정보가 없는 일회용 복사본에서 검증한다. 사람이 보는 상태는 검증 통과 또는 검증 실패다. Claude 시작 시간 중간값은 0.315초다. Codex는 미검증이라 띄우지 않는다.

## 결정

- 계획에 없는 단위와 작업 폴더가 없는 단위는 거부하고 프로세스를 만들지 않는다.
- 계획에 있는 단위는 노트 루트의 형제 `dam-<작업ID>`에서만 띄운다. handle은 노트 루트에 둔다.
- 제품 명령은 claude의 절대 경로만 실행한다. 테스트는 `ORCH_CLAUDE=-`라 PATH를 보지 않는다.
- 횟수 상한은 40이다. 임시이고 측정 뒤 고친다.
- push, PR, 머지 도구는 ADR 0007 제안대로 넘긴다. 새 토큰, 샌드박스 해제, 새 훅은 없다.
- Codex는 거부하고 띄우지 않는다.
- 허용 결정은 단위 이름 목록을 갖고, 공개 줄은 그 목록을 이어 붙인 것이다. 시작은 목록을 쓴다.
- 출력 형식은 stream-json이다. 첫 이벤트까지 걸린 시간은 공개 다섯 칸 밖에 둔다. 중간값 자체는 아직 노트에 없다.
- 워커가 노트에서 쓰는 곳은 `.team/sessions/<작업ID>/result.md`의 `## 결과` 절뿐이다. 결정은 `docs/adr/0009-worker-result-section.md`다.
- 워커는 원격에 쓰지 않는다. Bash와 MCP도 주지 않는다. `--tools`는 Read, Edit, Write다. bare Edit, Write 허용은 폴더 밖을 열므로 넣지 않는다. push, PR, 병합은 데브가 한다.
- 실행 파일이 없거나 실행할 수 없으면 시작은 거부하고 핸들을 만들지 않는다. `ORCH_CLAUDE=-`는 테스트가 띄우지 않는 스위치라 대기 핸들을 남긴다.
- 전제는 수거가 워커 폴더에서 검증과 커밋을 돌린다는 것이었다. 워커는 결과 칸만 쓰므로 그 전제는 버렸다.
- 수거는 워커 폴더에서 아무것도 실행하지 않고 결과 한 줄만 읽는다. 기록과 커밋은 신뢰하는 저장소에서 한다.
- 결과 칸 밖의 변경은 실행 없이 거부한다. 공통 gitdir의 설정, 속성, 훅이 바뀌면 문제다. 결정 줄과 승인 줄은 핸들 폴더의 원래 내용과 줄 단위로 비교하고, 이유에 경로와 그 줄을 적는다. 줄당 200자, 최대 8줄이다. 그 밖 파일은 경로만 적는다. 해시는 lstat다. 링크면 문제이고 따라가지 않는다. 워커 폴더에는 쓰지 않는다.
- 끝과 대기는 한 판단이다. 종료 파일이 있고 세션 그룹이 비었으면 끝이다. 그룹에 프로세스가 있으면 대기이고 결과 줄을 읽지 않는다.
- `성공`일 때만 사람이 노트 루트에서 결과 파일 하나를 훅과 fsmonitor를 끈 `git add`와 `git commit`으로 담는다. add의 clean filter는 그 저장소에 이미 있는 설정이다. 그룹은 bash 내장 `kill -TERM -<pid>`로 끝낸다. `/bin/kill`은 그룹을 못 끝낼 수 있다. 워커 폴더는 그룹이 빈 뒤 `git worktree remove`로 지운다.
- 넘기는 글은 맡은 단위의 이름, 의존, 파일, 검증과 결과 칸에 쓰는 법뿐이다.
- 승인 줄의 도구 칸 판정은 바꾸지 않는다.
- 로그 도구 칸은 Cursor다.
- 검증은 수거가 성공한 뒤에만, 네트워크와 인증 정보가 없는 일회용 복사본에서 한다. 사람이 보는 상태는 검증 통과 또는 검증 실패다. 워커의 통과 주장은 상태로 쓰지 않는다. 기록과 커밋은 검증 통과 뒤에만 안내한다.
- HR P PC 결과 칸은 비워 둔다.
