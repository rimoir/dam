# native 시작은 여기서 멈춘다

실제 워커 시작은 하지 않는다. 이 문서는 그 이유와, 확인 뒤에 할 일만 적는다.

## 멈춘 이유

`docs/milestones/m5b-hr-p-check.md`의 결과 칸은 모두 `결과: 아직 없음`이다. #77이 HR P PC에서 채워지기 전에는 #78의 실제 시작을 확정하지 않는다. 이슈 본문도 실행 확인 결과가 나오기 전에는 실제 시작 구현을 시작하지 말라고 한다.

## 보안 경계는 그대로 둔다

워커에게 처음부터 push, PR, 머지 도구를 주는 일은 ADR 0007에 제안으로 적혀 있다. HR P가 직접 확인하기 전에는 채택이 아니다. 이 변경은 그 경계를 열지 않는다.

- 새 토큰을 만들지 않는다. 좁은 토큰이나 GitHub App도 HR P 답 전에 시작하지 않는다.
- 승인과 샌드박스를 끄지 않는다. 훅 신뢰 우회와 새 훅도 없다.
- `scripts/issue_tracker.py`의 쓰기 함수는 사람이 명령했을 때만 gh를 부른다. 그 검사를 느슨하게 하지 않는다.
- 허용 목록의 명령 글자만으로 경계를 삼지 않는다.

Codex가 작업 폴더 커밋을 막으면 샌드박스를 풀지 않고 #78은 계속 멈춘다. 대안을 고르는 일은 5번 결과 다음이고, 풀지는 HR P가 정한다.

## 확인 뒤에 할 일

1. #77 칸을 읽고 버전과 Codex 커밋 결과를 적는다.
2. Claude Code가 v2.1.259보다 낮으면 그 사실을 알린다. 샌드박스를 끄는 쪽으로 바꾸지 않는다.
3. Codex가 커밋을 막으면 여기서 다시 멈춘다.
4. 막지 않으면 native 어댑터가 작업 폴더에서 비대화형 실행을 띄운다. 기본 도구는 메인 세션과 같은 도구다.
5. 시작 시간은 명령부터 첫 이벤트까지, 두 도구 각 5회 중간값으로 작업 노트에 적는다. 15초 제안은 측정 뒤에 고친다.
6. 워커마다 횟수 상한을 둔다.
7. 출력 파일의 토큰 가리기는 지금 수거 경로를 그대로 쓴다.

## 하지 않은 것

`scripts/orchestrator.py`에 claude나 codex를 띄우는 코드는 없다. push, PR, 머지 도구도 넣지 않았다. 시작 시간 중간값도 아직 없다.
