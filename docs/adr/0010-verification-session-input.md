# 0010. 검증 세션 시작 입력

## 상태

채택. 2026-11-27. 입력 제한 방식은 이슈의 열린 질문이 데브에게 맡긴 것이다. 보안 항목 경로 목록은 제안만이고, 감지하거나 다른 도구 검증을 강제하지 않는다.

## 결정

검증 세션의 시작 출력은 작성 세션의 시작 출력과 다른 명령이다.

```
python3 scripts/team-session.py start-context --role 검증 --criteria <완료 기준> --base <SHA> --head <SHA> --checks <검사 명령>
```

역할 값은 `검증`뿐이다. 환경 변수로 역할을 넘기지 않는다. 환경 변수는 명령 기록에 남지 않는다. 훅 파일은 바꾸지 않는다. `.claude/settings.json`과 `.codex/hooks.json`은 역할 없는 `start-context`를 그대로 호출한다.

이 출력이 검증 세션이 시작 때 받는 입력의 전부다. 네 칸만 낸다.

- 완료 기준
- BASE
- HEAD
- 검사 명령

현황판, state.md, log.md, task.md, result.md는 열지 않는다. 작성 세션의 결정 메모는 state.md의 `## 결정`에 있다. 그 파일을 읽지 않으므로 검증 출력에 들어가지 않는다. 만든 세션과 다른 세션인지는 새 세션 식별자로 나누지 않는다. 같은 트리에서 역할 없는 시작 출력에는 결정 메모가 있고, 검증 역할 출력에는 없다는 내용 차이로 확인한다.

SHA는 40자리 소문자 16진수다. 완료 기준과 검사 명령은 비어 있으면 실패한다. 글자 수가 시작 주입 상한 4,000자를 넘으면 본문을 줄이는 대신 실패한다. 줄이면 허용된 입력도 사라지기 때문이다. `--switch`와 함께 쓰면 실패한다. 스위치는 로그 마지막 줄을 더하고, 그 줄은 검증 입력이 아니다. 역할 없이 네 인자만 넘기면 실패한다. 작성 세션 출력에 검증 인자가 섞이지 않게 한다.

완료 기준과 검사 명령은 호출자가 인자로 넘긴다. task.md나 워크플로 파일에서 읽지 않는다. 그 파일의 다른 절에 있는 작성자 메모가 따라 들어오지 않게 한다.

역할이 없으면 지금까지의 시작 출력과 같다. 현황판의 열린 줄과 브랜치 끝 작업의 state.md다. 워커에게 넘기는 글은 `scripts/orchestrator.py`의 단위 프롬프트이고, 이 결정이 그 글을 바꾸지 않는다.

훅 파일은 그대로 둔다. 역할 없는 `start-context`는 작성 세션용이다. 브랜치 이름이 이슈 번호로 끝나면 그 명령은 state.md의 결정 메모를 넣는다. 검증 세션은 그 훅이 돌지 않는 자리에서 띄운다.

그 자리는 오케스트레이터가 이미 쓰는 일회용 복사본 격리다. `python3 scripts/team-session.py verify-session --criteria <완료 기준> --base <SHA> --head <SHA> --checks <검사 명령>`이 복사본을 만들고, 복사본에서 `.claude/settings.json`과 `.codex/hooks.json`만 지운 뒤, 네 칸을 그 프로세스의 첫 입력으로 넘긴다. 다이제스트나 작성 세션 id는 넘기지 않는다. 격리의 `env -i`가 부모 환경을 비운다. 마운트와 권한 경계는 바꾸지 않는다. 저장소의 훅 파일은 한 글자도 바꾸지 않는다.

이 격리는 Linux `unshare`가 필요하다. macOS에는 `unshare`가 없다. 준비가 실패하면 검증 세션을 띄우지 않고 실패로 끝낸다. 훅 있는 세션으로 넘어가지 않는다. 그래서 훅 자리가 깨져도 결정 메모가 검증 입력으로 들어가지 않는다.

검증 세션이 받은 첫 입력은 그 프로세스의 표준 출력으로 확인한다. 완료 기준, BASE, HEAD, 검사 명령만 있고, 작성 세션의 결정 메모와 `.team` 기록과 세션 id는 입력과 환경에 없다.

보안 항목을 건드리는 변경에 다른 도구 검증을 쓸 때의 경로 제안이다. 이 목록으로 막거나 검사하지 않는다.

| 경로 | 항목 |
|---|---|
| `.claude/settings.json` | 훅 |
| `.codex/hooks.json` | 훅 |
| `.github/workflows/ci.yml` | 권한 |
| `scripts/issue_tracker.py` | 토큰과 GitHub 쓰기 |
| `scripts/orchestrator.py` | 샌드박스와 제한 모드 |
| `.team/adapters.lock` | 토큰을 적으면 안 되는 어댑터 선택 |

브랜치 보호는 저장소 파일이 아니다. GitHub 설정이라 이 목록에 경로가 없다.

## 이유

검증 세션이 작성자의 결정 메모를 시작 때 받지 않게 하려고다. 역할 인자는 명령에 남고, 훅을 열지 않아도 출력을 가릴 수 있다. 기본 시작 출력과 워커 프롬프트는 이 역할 밖에서 그대로다.
