# 0011. 검증 결과 판정과 읽기 전용

## 상태

채택. 2026-11-27. 경로 목록과 `git status` 이름 비교는 되돌린 파일과 무시된 파일을 놓쳤다. 같은 날 내용 해시와 lstat 스냅샷으로 바꾼다. 훅 파일은 이 결정이 바꾸지 않는다.

## 결정

검증 결과 판정은 순수 함수다. 입력은 검증 출력 문자열과 기대 헤드 SHA다. 깃을 읽지 않고 노트를 열지 않는다.

출력 문자열은 빈 줄을 제외하고 네 줄이다.

```
PASS
헤드 SHA: <40자리 소문자 16진수>
확인 방법: <실행한 명령>
증거 요약: <한 줄>
```

첫 줄은 `PASS`, `ISSUES`, `BLOCKED` 중 정확히 하나다. 확인 방법과 증거 요약은 비어 있으면 안 된다. 헤드 SHA는 기대 값과 같아야 한다. 줄이 모자라거나, 칸이 비거나, 헤드가 다르면 판정은 `실패`다. `실패`는 통과가 아니다. `ISSUES`와 `BLOCKED`는 그 단어 그대로 돌려주고 통과가 아니다. 통과는 `PASS`뿐이다.

명령은 `python3 scripts/team-session.py verify-judge --head <SHA> --text <결과>`다. 표준 출력은 판정 한 단어다. 종료 0은 `PASS`일 때다.

읽기 전용은 호출자가 적은 경로 목록이나 `git status` 이름으로 가리지 않는다. 그 방식은 파일을 바꿨다 되돌리거나 `.gitignore`된 파일을 더해도 `깨끗`이 되었다. 명령이 작업 폴더를 직접 걷는다.

시작은 `python3 scripts/team-session.py verify-readonly --begin --snapshot <파일>`이다. 명령이 코드 파일의 스냅샷을 만들어 그 파일에 쓴다. 스냅샷 파일은 작업 폴더 밖이어야 한다. 안이면 `실패`이고 쓰지 않는다. 표준 출력은 그 파일 바이트의 sha256 64자리 소문자다. 이 다이제스트는 검증을 벌이는 호출자가 갖는다. 검증 세션 시작 입력은 완료 기준, BASE, HEAD, 검사 명령만이고 다이제스트는 넣지 않는다.

끝은 `python3 scripts/team-session.py verify-readonly --end --snapshot <같은 파일> --expect <다이제스트>`다. `--expect`가 없거나 64자리 소문자 16진수가 아니면 `실패`다. 스냅샷 파일의 sha256이 `--expect`와 다르면 `실패`다. `--begin`을 다시 돌리거나 JSON을 덮어쓰면 파일 다이제스트가 달라져 실패다. 다이제스트가 같을 때만 트리를 다시 찍어 비교한다. 시작 파일이 없거나, 읽을 수 없거나, 스냅샷이 아니면 `실패`다.

스냅샷에 넣는 파일은 추적된 파일, 추적되지 않은 파일, `.gitignore`된 파일이다. `.git`과 `.team/`은 걷지 않는다. 일반 파일은 내용의 sha256과 lstat다. lstat는 종류, 모드, 크기, inode, mtime_ns, ctime_ns다. 심볼릭 링크는 따라가지 않고 링크 대상을 적는다. 내용 해시가 같아도 lstat가 다르면 `실패`다. 그래서 내용을 되돌린 파일도 실패다. `.team/`만 바뀌면 스냅샷이 같아서 `깨끗`이다.

끝의 표준 출력은 `깨끗` 또는 `실패`다. 시작의 표준 출력은 다이제스트다. 실패면 달라진 상대 경로를 표준 오류에 적는다. 종료 0은 `깨끗`일 때와 시작을 찍었을 때다.

파일 형식을 바꿔도 검증 세션이 스냅샷을 읽고 `--begin`을 다시 돌릴 수 있으면, 새 다이제스트로 `--end`가 `깨끗`이 된다. 시작 기록은 검증 세션이 볼 수 없는 곳에 둔다. 호출자는 오케스트레이터이고 격리 밖에 있다. 명령은 `python3 scripts/team-session.py verify-readonly --isolated --snapshot <작업 폴더 밖 파일> --command <검증 명령>`이다. 이 프로세스가 다이제스트를 메모리에만 갖고, 스냅샷 파일은 일회용 복사본과 격리 루트에 넣지 않는다. 검증 명령은 이미 있는 일회용 복사본 격리에서 돈다. 마운트와 권한 경계는 바꾸지 않는다. 격리 안에서 스냅샷 경로가 보이면 `실패`다. 격리된 명령이 코드를 바꾸고 스냅샷을 다시 찍거나 덮어써도, 호출자가 가진 다이제스트는 그대로라 끝 비교는 `실패`다. 다이제스트는 검증 세션 표준 출력으로 돌려주지 않는다.

이 격리는 Linux `unshare`가 필요하다. macOS에는 `unshare`가 없다. 그 환경에서는 격리 읽기 전용 확인이 `실패`다.

`code-clean` 명령은 이 결정이 바꾸지 않는다. 읽기 전용 판정은 그 명령의 porcelain을 보지 않는다.

이 판정은 워커 수거가 쓰는 `judge`와 다른 함수다. 워커 판정은 결과 칸 한 줄과 종료 코드와 다음 할 일 갱신을 본다. 그 함수는 이 결정이 바꾸지 않는다. `code-clean`의 종료 코드와 표준 오류도 그대로다.

훅 파일은 열지 않는다. 새 훅과 새 토큰은 없다. 검증 세션의 권한 목록은 늘리지 않는다. 결과 기록과 PR 코멘트는 이 결정 밖이다.

## 이유

가짜 검증 문자열만으로 통과 여부를 가르고, 검증 중에 파일 내용이나 lstat가 달라지면 그 검증을 실패로 두려고다. 시작 기록은 명령이 작업 폴더 밖에 쓴다. 판정은 훅에 기대지 않는다.
