# 0011. 검증 결과 판정과 읽기 전용

## 상태

채택. 2026-11-27. 결과 형식과 읽기 전용 확인은 이슈 메모가 순수 함수와 `code-clean` 두 번 호출을 제안한 것이다. 훅 파일은 이 결정이 바꾸지 않는다.

## 결정

검증 결과 판정은 순수 함수다. 입력은 검증 출력 문자열과 기대 헤드 SHA다. 깃을 읽지 않고 노트를 열지 않는다.

출력 문자열은 빈 줄을 제외하고 네 줄이다.

```
PASS
헤드 SHA: <40자리 소문자 16진수>
확인 방법: <실행한 명령>
증거 요약: <한 줄>
```

첫 줄은 `PASS`, `ISSUES`, `BLOCKED` 중 정확히 하나다. 확인 방법과 증거 요약은 비어 있으면 안 된다. 헤드 SHA는 기대 값과 같아야 한다. 줄이 모자라거나, 칸이 비거나, 헤드가 다르면 판정은 `실패`다. `실패`는 통과가 아니다. `ISSUES`와 `BLOCKED`는 그 단어 그대로 돌려주고 통과가 아니다. 통과는 `PASS`뿐이다.

명령은 `python3 scripts/team-session.py verify-judge --head <SHA> --text <결과>`다. 표준 출력은 판정 한 단어다. 종료 0은 `PASS`일 때다.

읽기 전용은 #66의 `code-clean`이 보는 코드 경로를 시작과 끝에 각각 본다. 시작 경로는 `--before` 파일에 한 줄에 하나다. 끝 경로는 그 순간 `code-clean`과 같은 `code_dirty_paths`다. `.team/` 아래는 코드 경로가 아니다. 시작 경로나 끝 경로가 하나라도 있으면 판정은 `실패`다. 둘 다 비어 있으면 `깨끗`이다. 끝이 더러우면 실패라는 제안과 같다. 시작이 더러운 채로 끝나면 검증 중에 깨끗해졌는지와 상관없이 실패다. 바뀐 내용을 되돌린 뒤의 깨끗한 트리는 이 검사가 시작 목록 없이 보면 깨끗한 것으로 남는다. 그래서 시작 목록을 넘긴다.

명령은 `python3 scripts/team-session.py verify-readonly --before <파일>`이다. `--before`가 없으면 시작 경로는 비어 있고, 지금 트리만 끝으로 본다. 표준 출력은 `깨끗` 또는 `실패`다. 실패면 끝 경로를 표준 오류에 적는다. 종료 0은 `깨끗`일 때다. 시작 목록 파일은 `.team/` 아래나 작업 트리 밖에 둔다. 트리 안에 두면 `code-clean`이 그 파일을 코드 경로로 본다.

이 판정은 워커 수거가 쓰는 `judge`와 다른 함수다. 워커 판정은 결과 칸 한 줄과 종료 코드와 다음 할 일 갱신을 본다. 그 함수는 이 결정이 바꾸지 않는다. `code-clean`의 종료 코드와 표준 오류도 그대로다.

훅 파일은 열지 않는다. 새 훅과 새 토큰은 없다. 검증 세션의 권한 목록은 늘리지 않는다. 결과 기록과 PR 코멘트는 이 결정 밖이다.

## 이유

가짜 검증 문자열만으로 통과 여부를 가르고, 검증 중에 코드 경로가 생기면 그 검증을 실패로 두려고다. 판정은 파일과 훅에 기대지 않는다.
