# 0009. 워커는 결과 칸만 쓴다

## 상태

채택. 2026-11-27. HR P가 09:44 KST에 직접 정한 문장이다. 기록은 이슈 코멘트에 있다.

원문: "워커는 결과 칸만 쓰게 하고, 결정 줄이나 승인 줄을 바꾸면 결과를 받지 마. 단위만 넘겨"

출처: https://github.com/rimoir/dam/issues/78#issuecomment-7206721782

## 결정

워커가 노트에서 쓸 수 있는 곳은 결과 칸뿐이다. 작업 폴더의 코드는 이 결정이 막지 않는다. 워커는 원격에 쓰지 않는다. push, PR, 병합은 데브가 한다. 워커에게 Bash를 주지 않는다. 조회와 차이도 주지 않는다. 읽기와 파일 쓰기는 Claude Code의 Read, Edit, Write로 한다. 코드 실행과 커밋은 워커에게 주지 않는다. 띄울 때 `--restricted --strict-mcp-config`를 넣는다. `--mcp-config`는 넣지 않는다. `--strict-mcp-config`만 두면 사용자 설정의 MCP는 열리지 않고, 넘긴 서버도 없으므로 MCP가 없다. `--restricted`는 명령과 코드를 실행하는 내장 도구와 WebFetch를 `--tools`가 이름으로 부르지 않는 한 없애고, 파일 도구를 작업 디렉터리 안으로 가둔다. `--tools`는 `Read,Edit,Write`다. `--permission-prompts none`이라 작업 폴더 밖 쓰기와 git 설정 쓰기처럼 사람이 승인해야 하는 요청은 거부된다. bare `Edit`나 `Write` 허용은 작업 디렉터리 밖 경로를 미리 승인하므로 `--allowedTools`에 그 이름을 넣지 않는다. 작업 폴더 안 쓰기는 `--permission-mode acceptEdits`가 받는다. `--disallowedTools Bash`는 `--restricted`와 겹친다. 거부 규칙을 남겨, `--tools`에 Bash가 다시 들어와도 거부가 이기게 한다.

전제는 수거가 워커 폴더에서 검증 코드와 git commit을 돌린다는 것이었다. 그 전제는 틀렸다. 워커는 결과 칸만 쓰므로, 워커 쪽에는 검증하거나 커밋할 코드 변경이 없다. 수거는 워커 폴더에서 아무것도 실행하지 않고 결과 한 줄만 읽는다. 기록과 커밋은 신뢰하는 저장소에서 한다. 결과 칸 밖의 변경은 실행 없이 거부한다.

워커는 새 세션으로 띄운다. 끝인지 대기인지는 한 곳에서만 판단한다. 종료 파일이 있고 세션 그룹이 비었으면 끝이다. 그룹에 살아 있는 프로세스가 있으면 대기이고, 그때는 결과 줄을 읽지 않는다. 종료 파일이 없고 그룹이 살아 있으면 진행이다. poll과 수거가 그 판단을 같이 쓴다. 멈출 때와 폴더를 지울 때는 bash 내장 `kill -TERM -<pid>`로 그룹 전체를 끝낸다. `/bin/kill`은 같은 문자를 쳐도 그룹을 못 끝낼 수 있다. pid는 핸들에 적힌 세션 리더다. 워커가 새 세션을 만들어 그룹 밖으로 빠지는 실행은 두지 않는다. Bash가 없으므로 `setsid`나 `diff.external`을 띄울 수 없다. 해시는 lstat로만 뜬다. 작업 폴더와 함께 공통 gitdir의 `config`, `info/attributes`, `hooks/`를 시작 때 파이썬으로만 떠 둔다. 거둘 때 그것이 바뀌면 문제다. 시작 때 없던 심볼릭 링크가 생기거나 링크 대상이 바뀌면 문제다. result.md는 일반 파일일 때만 읽고, 링크면 문제다. 읽을 때 링크를 따라가지 않는다. 수거는 워커 폴더에 쓰지 않는다.

검증은 수거가 `성공`인 뒤에만, 네트워크와 인증 정보가 없는 일회용 복사본에서 돌린다. 복사본은 거둘 때 검사한 작업 폴더 내용이다. 브랜치 ref를 꺼내지 않는다. 검사와 복사 사이에 그 내용이 바뀌면 `검증 실패`이고 명령은 돌리지 않는다. 명령은 복사본, 임시 HOME, 런타임에 필요한 경로만 보이는 최소 루트에서 돈다. 호스트의 `/dev/shm`, `/run`, `/tmp`, `/var`는 그 루트에 없다. 새 PID namespace의 init이 끝나면 빠져나간 프로세스도 죽는다. 마운트를 준비한 뒤 중첩 user namespace로 상위 마운트를 잠그고 capability를 버린 다음에 명령을 돌린다. 준비가 실패하면 명령을 돌리지 않고 `검증 실패`와 이유를 낸다. 사람이 보는 상태는 `검증 통과` 또는 `검증 실패`다. 워커가 적은 통과 주장은 상태로 쓰지 않는다. 워커에게 넘기는 글에는 검증 지시가 없다. 네트워크나 홈을 가리지 못하면 검증을 돌리지 않고 `검증 실패`와 이유를 낸다. 이 결정은 2026-11-27 16:46 KST에 HR P가 고른 1번이다. 원문: "1번으로 해. 수거가 성공하면 네트워크와 인증 정보 없는 일회용 복사본에서 검증해". 출처는 https://github.com/rimoir/dam/issues/78#issuecomment-7212804779 이고, 원인과 세 대안은 https://github.com/rimoir/dam/issues/78#issuecomment-7210845998 이다. 2번은 워커에게 셸을 다시 주어 통과 주장이 워커 말로 남는다. 3번은 결과를 보려면 push와 PR까지 가야 해서 단위의 끝을 바로 알 수 없다. 그래서 1번만 고른다.

기록과 커밋은 사람이 신뢰하는 저장소, 곧 노트 루트에서 한다. `python3 scripts/orchestrator.py collect --handle <핸들>`이 돌려준 `line`이 결과 줄이다. `state`가 `검증 통과`일 때만 그 줄을 노트 루트 `.team/sessions/<작업ID>/result.md`의 `## 결과` 다음 첫 줄로 넣고, 같은 저장소에서 다음만 실행한다. `git -c core.hooksPath=/dev/null -c core.fsmonitor=false add -- .team/sessions/<작업ID>/result.md` 뒤에 `git -c core.hooksPath=/dev/null -c core.fsmonitor=false commit`으로 담는다. add가 실행하는 clean filter는 신뢰하는 저장소에 이미 있는 설정이다. `검증 통과`가 아니면 이 git을 돌리지 않는다. 워커 폴더에서는 git을 돌리지 않는다. 그룹에 프로세스가 없을 때 노트 루트에서 `git worktree remove --force ../dam-<작업ID>`로 워커 폴더를 지우고, `git branch -D worker/<작업ID>`로 브랜치를 지운다.

결과 칸은 `.team/sessions/<작업ID>/result.md`의 `## 결과` 제목 다음 줄부터, 다음 `## ` 제목 직전까지다. 제목 줄 자체와 `## 교훈 후보` 같은 다른 절은 결과 칸이 아니다.

결정 줄은 같은 세션 `state.md`의 `## 결정` 절 안에 있는 줄이다. 승인 줄은 같은 세션 `log.md`에서 시작 허용이 승인으로 세는 줄이다. 도구 칸이 `Claude Code` 또는 `Codex`이고 그 다음 칸이 승인인 줄만 승인 줄이다. 도구 칸이 `Cursor`인 줄은 승인으로 세지 않는다. 그 판정은 이 결정이 바꾸지 않는다.

시작은 띄우기 전에 노트 루트와 작업 폴더의 결정 줄과 승인 줄을 간직한다. 거둘 때 그 줄이 바뀌거나 더해졌으면 결과 칸을 받지 않는다. 공개 칸은 그대로다. `state`는 `문제`이고 `line`은 비운다. `reason`에는 경로와 바뀐 줄을 적는다. `state.md`와 `log.md`의 원래 내용은 시작 때 핸들 폴더에 둔다. 거둘 때는 워커 폴더를 lstat와 링크를 따라가지 않는 읽기로만 보아 줄 단위로 비교한다. 바뀐 줄은 줄당 200자, 최대 8줄이고 제어 문자는 이스케이프한다. 그 밖 파일은 경로만 적는다. 노트 루트의 그 줄만 간직했던 내용으로 되돌린다. 워커 폴더는 쓰지 않는다. 워커가 쓴 승인 줄은 노트 루트에 남지 않고, 다음 시작의 승인 판정에 읽히지 않는다.

워커에게 넘기는 글은 맡은 단위뿐이다. 이름, 의존, 파일, 그리고 결과 칸에 쓰는 법만 넣는다. 검증 지시는 넣지 않는다. 다른 단위와 `state.md`의 결정 줄은 넣지 않는다.

## 이유

워커가 결정 줄과 승인 줄을 직접 쓰면, 시작 허용이 그 줄을 읽어 다음 단위를 스스로 열 수 있다. 결과 칸만 받고, 노트 루트의 그 줄을 되돌리면 그 길이 막힌다. 수거가 워커 폴더의 코드나 git을 돌리면, 결과 칸 밖에 심어 둔 설정과 파일이 실행된다. 실행할 변경이 없으므로 그 실행을 두지 않는다. `git diff`의 `diff.external`도 같은 실행이다. Bash를 빼면 그 프로그램과 새 세션으로 빠지는 실행이 생기지 않는다. 그래서 단위 검증을 돌릴 주체가 없어졌고, 워커는 통과를 주장만 하게 됐다. 검증은 신뢰 쪽이 검사한 작업 폴더의 일회용 복사본에서 돌리고, 그 결과만 상태로 보인다. 막을 경로를 나열하면 빠뜨린 소켓과 `/dev/shm`로 호스트와 통하고, 세션을 벗어난 프로세스는 그룹이 끝나도 남는다. 그래서 보이는 경로를 허용한 것만 두고, 프로세스 수명은 PID namespace의 init에 묶는다.
