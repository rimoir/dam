# 0008. 모드 선언

## 상태

채택. 2026-11-26. 모드를 고르는 기준과 확실하지 않음의 기준은 추정이다. 스펙의 기준으로 시작하고, 자기 작업 10건 뒤에 고친다. HR P 사후 확인.

## 결정

모드는 넷뿐이다. 모드 이름: 조사, 작은 수정, 기능, 이어받기.

첫 답은 세 줄이다. 모드와 이유 한 줄, 작업 이름, state.md의 다음 할 일. Claude Code와 Codex가 같다. 열린 작업이 없으면 작업 줄의 문구는 뒤 이슈가 정한다.

고른 모드는 열린 작업 state.md 첫 줄에 남는다. 형식은 `모드: <이름>`이다. 시작 출력이 그 줄을 싣는다. 열린 작업이 없으면 파일을 만들지 않는다.

두 모드에 걸치면 세션당 질문은 한 번이다. 고를 것 둘과 기본값을 같이 적는다. 기본값은 코드를 덜 바꾸는 쪽이다. 답이 없어도 다시 묻지 않고 기본값을 쓴다.

고르는 기준은 추정이다.

- 조사: 코드를 바꾸지 않고 읽고 답한다.
- 작은 수정: 한곳의 작은 코드 변경이다.
- 기능: 새 동작을 넣는다.
- 이어받기: 열린 작업의 지금 모드를 유지한다.
- 확실하지 않음: 요청이 위 둘 이상에 걸친다.

예시: "왜 실패하는지 보고 한 줄만 고쳐 달라"는 조사와 작은 수정에 걸친다. 질문 한 번. 고를 것 조사, 작은 수정. 기본값 조사.
예시: "버그를 고치며 새 흐름을 추가해 달라"는 작은 수정과 기능에 걸친다. 질문 한 번. 고를 것 작은 수정, 기능. 기본값 작은 수정.
예시: "지난 구현을 이어가되 원인부터 봐 달라"는 이어받기와 조사에 걸친다. 질문 한 번. 고를 것 이어받기, 조사. 기본값 조사.
예시: "기능은 그리되 코드는 넣지 말라"는 기능과 조사에 걸친다. 질문 한 번. 고를 것 기능, 조사. 기본값 조사.

두 도구의 실제 응답 확인은 사람 PC의 기록으로 남긴다. 이 결정의 검사는 규칙 원본의 모드 이름 넷과 생성물 일치까지다.

## 이유

일의 종류에 따라 첫 답이 모드를 말하게 하려고다. 질문은 세션당 한 번으로 두고, 예시와 기준은 규칙 원본 대신 여기에 두어 줄 수를 늘리지 않는다.
