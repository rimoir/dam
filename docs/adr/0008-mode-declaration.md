# 0008. 모드 선언

## 상태

채택. 2026-11-26. 모드를 고르는 기준과 확실하지 않음의 기준은 추정이다. 스펙의 기준으로 시작하고, 자기 작업 10건 뒤에 고친다. HR P 사후 확인.

## 결정

모드는 넷뿐이다. 모드 이름: 조사, 작은 수정, 기능, 이어받기.

첫 답은 세 줄이다. 모드와 이유 한 줄, 작업 이름, state.md의 다음 할 일. Claude Code와 Codex가 같다. 열린 작업이 없으면 작업 줄은 `작업: 없음 (열린 줄 N)`이다.

고른 모드는 열린 작업 state.md 첫 줄에 남는다. 형식은 `모드: <이름>`이다. 시작 출력이 그 줄을 싣는다. 열린 작업이 없으면 파일을 만들지 않는다.

두 모드에 걸치면 세션당 질문은 한 번이다. 고를 것 둘과 기본값을 같이 적는다. 기본값은 코드를 덜 바꾸는 쪽이다. 답이 없어도 다시 묻지 않고 기본값을 쓴다.

고르는 기준은 스펙에서 시작한다. 추정이다.

- 조사: 코드를 안 바꾼다. 답이 설명이나 추천이다. 읽고 근거를 달아 답한다. 코드 파일 변경은 0이고 go는 없다.
- 작은 수정: 한두 파일, 접근이 뻔함, 새 의존 없음. task.md에 계획 한 줄, go 뒤 직접 고친다. 워커는 띄우지 않는다.
- 기능: 완료 기준 여러 개, 세 파일 이상, 또는 PR 여러 개. 질문하고 writing-plans로 task.md를 쓴 뒤 go에서 멈춘다.
- 이어받기: 브랜치 끝 번호의 state.md가 있거나 '이어서'라고 한다. state.md와 log.md로 멈춘 곳을 찾아 남은 일만 한다. 끝나면 원래 모드로 돌아간다.
- 확실하지 않음: 신호가 두 모드에 걸칠 때, 건드릴 파일 수를 말로 짐작할 수 없을 때, state.md에 적힌 모드와 지금 요청이 다를 때, 코드 변경 요청인데 브랜치에 이슈 번호가 없고 열린 작업도 고를 수 없을 때. 이때만 한 번 묻는다.

예시: "알아보고 고쳐 줘"는 조사와 작은 수정에 걸친다. 질문 한 번. 고를 것 조사, 작은 수정. 기본값 조사.
예시: "이 버그를 고쳐 달라"는 파일 수를 짐작할 수 없어 작은 수정과 기능에 걸친다. 질문 한 번. 고를 것 작은 수정, 기능. 기본값 작은 수정.
예시: state.md가 `모드: 조사`인데 "세 파일에 새 동작을 넣어 달라"고 하면 조사와 기능에 걸친다. 질문 한 번. 고를 것 조사, 기능. 기본값 조사.
예시: "한 파일의 오타를 고쳐 달라"인데 브랜치에 이슈 번호가 없고 열린 작업도 없으면 조사와 작은 수정에 걸친다. 질문 한 번. 고를 것 조사, 작은 수정. 기본값 조사.

두 도구의 실제 응답 확인은 사람 PC의 기록으로 남긴다. 이 결정의 검사는 규칙 원본의 모드 이름 넷과 생성물 일치까지다.

줄 수 상한은 규칙 원본 50줄, 모드 명령 본문 40줄로 확정한다. 측정값은 규칙 원본 39줄, 명령 본문 10줄이라 제안값 안이다. 상한은 올리지 않는다. `python3 scripts/team-session.py check`가 넘거나 두 본문이 다르면 실패한다.

## 이유

일의 종류에 따라 첫 답이 모드를 말하게 하려고다. 질문은 세션당 한 번으로 두고, 예시와 기준은 규칙 원본 대신 여기에 두어 줄 수를 늘리지 않는다.
