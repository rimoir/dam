# 0007. 워커의 GitHub 쓰기와 머지

## 상태

제안. 2026-11-26. HR P가 이 이슈 코멘트나 PR 승인으로 두 보안 결정을 직접 확인하기 전에는 채택하지 않는다. 확인 기록은 PM이 중계한 것이고, HR P가 직접 남긴 이슈 코멘트는 아직 없다.

## 결정

계획 go 뒤에 워커는 그 작업 브랜치로만 push한다. PR을 열고, PR에 검토 코멘트를 남긴다. 아래를 모두 지키면 squash 머지할 수 있다.

- 최종 head에서 검사 세 개(python test, rulesync regen, gitleaks)가 성공한다
- 검토 기록이 있다
- pull request를 연 뒤 1분이 지났다

이슈 라벨을 바꾸거나 이슈를 직접 닫지 않는다. main이나 다른 브랜치로 push하지 않는다. force push를 하지 않는다.

워커 결과의 push는 `python3 scripts/team-session.py worker-push`다. HR P 승인 기록 줄이 있고, 현재 브랜치와 대상이 그 작업 브랜치(끝이 이슈 번호)일 때만 `git push`를 부른다. main, 다른 브랜치, force는 이유를 내고 거부한다. PR은 사람이 치는 `pull`과 같은 `open_work_pr`를 호출한다. 그 함수가 실패하면 log.md는 바이트 그대로다. 날 `git push`는 이 가드가 막지 못한다. 그 경계는 https://github.com/rimoir/dam/issues/88 이다.

두 보안 결정. 워커에게 처음부터 push, PR, 머지 도구를 준다. HR P가 2026-11-26 12:47 KST(Asia/Seoul)에 정한 문장이다.

- "워커한테 처음부터 push·PR·머지 도구까지 다 줘"
- "헤드 SHA, 확인 방법, 증거가 있는 다른 세션 검증 코멘트는 리뷰 기록으로 쳐"

같은 대화의 앞선 발언이다.

- 12:39 KST: "워커 push와 PR 열기까지 허용, 머지만 내가"
- 12:41 KST: "pr머지도 리뷰하고 ci통과 했으면 하도록 해 중요한 결정 보안적인것만 내 의견 받고"

이 결정은 12:47의 문장을 따른다. 검토 기록과 검사 통과 뒤의 머지를 포함하고, 중요한 보안 결정만 HR P 의견을 받는다. 기록은 PM이 중계했다.

출처: https://github.com/rimoir/dam/issues/4#issuecomment-7182074410
원문 중계: https://github.com/rimoir/dam/issues/60#issuecomment-7183757371

만든 세션과 다른 세션의 검증 코멘트를 검토 기록으로 치려면 헤드 SHA, 확인 방법, 증거가 있어야 한다. 거기에 검증 세션 id가 없으면 검토 기록이 아니다. 세션 id가 없거나 헤드가 지금 PR 헤드와 다르면 그 코멘트는 기록이 아니다. 첫 줄 표식만으로는 기록이 되지 않는다. #56에서 만든 세션의 자기 검증 코멘트가 기록으로 통과한 일이 있다 (https://github.com/rimoir/dam/issues/56#issuecomment-7186535471). 판정은 `docs/adr/0013-verification-comment.md`다. 사람이 머지하는 경로의 검토 기록 정의는 ADR 0003에 그대로 둔다.

다른 도구 검증이 필요한 보안 항목 경로는 `docs/adr/0010-verification-session-input.md`의 제안 표다. 그 표로 막거나 검사하지 않는다. 브랜치 보호는 저장소 파일이 아니다.

같은 GitHub 계정이 PR을 쓰고, 검증 코멘트를 남기고, 머지할 수 있다. 사람이 한 일과 구분하기 어렵다.

경계는 명령 글자 허용 목록이 아니다. OS 샌드박스, 토큰 권한, GitHub 쪽 규칙이 맡는다.

새 토큰은 만들지 않는다. 이 줄은 HR P 답이 나올 때까지 그대로다. 좁은 토큰을 쓸지는 이 결정이 정하지 않는다.

`docs/conventions.md`의 역할 표는 PM 봇, 데브 봇, 리서치 봇의 규칙이다. 제품 워커의 쓰기와 머지는 이 결정이 정한다. 그 표는 바꾸지 않는다.

이 결정은 규칙 원본의 '사람이 직접 명령했을 때만'과 'PR은 자동으로 열지 않는다', ADR 0005의 사람 명령 문장, ADR 0003의 검토 기록과 머지 주체를 워커 경로에 한해 대체한다. 사람이 이미 로그인한 gh만 쓴다는 점, 새 토큰을 만들지 않는다는 점, 작업 시작 명령이 읽기만 한다는 점은 그대로다.

이 기록은 문장만 바꾼다. `scripts/issue_tracker.py`의 쓰기 함수는 `commanded`가 아니면 그대로 거부한다. 스크립트는 사람과 워커를 구분하지 않는다. 라벨 변경과 이슈 닫기를 하지 않는 금지는 워커가 지키는 규칙이고, 새 코드 분기는 없다. `pull` 명령은 `commanded`를 참으로 넘긴다. 머지 명령은 이 저장소 스크립트에 없다.

저장소는 공개다. 2026-11-26에 GitHub API가 `private: false`로 답했다. 공개 여부를 바꿀지는 이 결정이 정하지 않는다.

## 이유

M5에서 워커가 계획 go 뒤에 자기 브랜치로 push하고 PR을 열며, 조건을 채우면 머지할 수 있게 하려고다. 보안 항목은 위 기록에 적힌 범위만 연다.
