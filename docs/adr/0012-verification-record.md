# 0012. 검증 결과를 노트에 남긴다

## 상태

채택. 2026-11-28. 훅 파일과 격리 코드는 이 결정이 바꾸지 않는다.

## 결정

판정을 통과한 검증만 그 작업의 result.md와 log.md에 남긴다. 통과는 `PASS`뿐이다. `ISSUES`와 `BLOCKED`는 판정 단어로 돌려주고 파일을 바꾸지 않는다. 칸이 빠지거나 헤드가 기대 SHA와 다르면 `실패`이고 파일은 그대로다.

명령은 `python3 scripts/team-session.py verify-record --work <작업ID> --tool <도구> --model <모델> --head <SHA> --text <결과>`다. 도구는 `Claude Code` 또는 `Codex`다. 그 밖이면 `실패`이고 쓰지 않는다.

result.md의 `## 결과`는 수거가 읽는 한 줄이다. `PASS 헤드 <7자> 모델 <모델>`. 증거 요약은 `## 증거 요약`에 둔다. `## 교훈 후보`는 둔다. 결과 칸에 증거 문장을 넣지 않는다.

log.md 한 줄은 기존 `YYYY-MM-DDTHH:MM:SSZ 도구 종류 내용`이다. 종류는 `종료`다. `go`는 승인으로 세므로 쓰지 않는다. 내용 칸은 `검증 PASS 모델 <모델> 헤드 <7자 SHA>`다. 200줄을 넘기면 기존 rotate가 앞부분을 `log/`로 옮긴다. 옮긴 내용은 바꾸지 않는다.

토큰과 주소 속 비밀번호, 그리고 `password`, `secret`, `token` 이름 뒤의 값은 `scripts/issue_tracker.py`의 가림 한 곳을 거친 뒤에 쓴다. 가린 값은 노트에 남지 않는다.
이름 없이 그냥 적힌 비밀번호는 범위 밖이다 (https://github.com/rimoir/dam/issues/81#issuecomment-7240213178).

이 명령은 노트를 쓴다. 판정 함수는 그대로 깃과 노트를 읽지 않는다. 워커 수거의 `judge`와 `code-clean`은 바꾸지 않는다. 훅 파일을 열지 않는다. 격리의 마운트와 권한은 바꾸지 않는다. PR 검토 코멘트는 이 결정 밖이다.

## 이유

검증이 통과했다는 사실이 그 작업 노트에 남아야 하고, 형식 불량이나 통과가 아닌 판정이 노트를 고치면 안 된다. 로그 종류를 새로 만들면 한 줄 형식이 바뀌므로, 기존 종류 가운데 승인으로 세지 않는 `종료`를 쓴다.
