# 0003. CI와 머지 규칙

## 상태

채택. 2026-11-26.

## 결정

main으로 가는 pull request와 main push에서 검사 세 개를 돌린다.

- python test: `python3 scripts/team-session_test.py`
- rulesync regen: rulesync `43.14.0`으로 다시 만든 뒤 `CLAUDE.md`와 `AGENTS.md`가 커밋과 같은지 본다
- gitleaks: `8.30.1`로 작업 트리(`--no-git`)와 그 PR이 더한 커밋을 본다

첫 CI pull request는 검사가 아직 없으므로, 코드를 보고 남긴 검토 기록이 한 건 이상이면 머지한다. 연 뒤 1분이 지나기 전에는 머지하지 않는다.

그 다음 pull request부터는 다음을 모두 지킨다.

- 검사 세 개가 통과한다
- 검토 기록이 있다. 검토 기록은 승인, 또는 사람이나 검토 봇이 코드를 보고 남긴 내용 있는 검토 코멘트다. "검토하지 못했다"는 봇 알림과 머지 자체는 기록이 아니다
- pull request를 연 뒤 1분 안에 머지하지 않는다
- 리뷰 없이 머지하지 않는다

main 브랜치 보호 규칙 또는 룰셋으로 위 검사와 검토 기록을 필수로 두는 것은 HR P가 적용한다. 데브는 저장소 설정을 바꾸지 않는다. 권고는 main에 대해 검사 세 개와 검토 기록을 요구하는 것이다. 이 비공개 저장소 요금제에서 설정으로 막을 수 없으면 그 확인 이슈는 시작하지 않고 대안을 기다린다.

## 이유

PR을 열면 테스트, 재생성 차이, 비밀 검사가 자동으로 돌게 하고, 통과와 검토 기록이 있는 변경만 main에 두려고다.
